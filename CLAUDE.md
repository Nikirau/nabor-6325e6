# Набор: питание и тренировки

Одностраничное приложение на чистом HTML/CSS/JS для набора массы, устанавливаемое как PWA (десктоп, iPhone, Android). Вся логика и интерфейс в одном файле [index.html](index.html), без сборщиков, фреймворков и внешних зависимостей. Интерфейс на русском. Пользуются двое, приложение личное: сайт не индексируется (`noindex`), личных данных в репозитории нет.

## Файлы

- `index.html`: всё приложение (стили, разметка, скрипт).
- `manifest.webmanifest`: имя, иконки, `display: standalone`, `start_url: "./"`. Пути относительные, чтобы работало в подпапке GitHub Pages (`user.github.io/repo/`).
- `sw.js`: service worker, стратегия «сначала сеть (`cache: 'no-cache'`), при отказе кэш». Правки `index.html` видны сразу после публикации, без интернета приложение открывается из кэша. Имя кэша `CACHE` менять только при изменении списка `SHELL` (новые файлы в оболочке приложения; новые файлы добавлять в `SHELL`).
- `icons/`: `icon-192.png`, `icon-512.png` (подходят и как maskable), `apple-touch-icon.png` для iOS. Иконка сгенерирована скриптом: штанга на тёмном фоне.
- `.claude/launch.json`: локальный сервер `python -m http.server 8123` для проверки (`preview_start nabor`).

## Как запускать и проверять

Service worker и установка PWA работают только по `http://localhost` или `https://`, не по `file://`. Для проверки запустить `python -m http.server 8123` в папке проекта и открыть `http://localhost:8123/`. Сама страница открывается и по `file://` (двойной клик), но без service worker, а данные `localStorage` у `file://` и у `localhost` разные.

Сборки и тестов нет. Проверка ручная: пройти разделы, перезагрузить страницу, убедиться, что данные на месте; в DevTools → Application проверить manifest и service worker.

Данные `localStorage` привязаны к адресу сайта и устройству, между устройствами не синхронизируются: перенос только через копию данных в профиле.

## Структура скрипта в index.html

Один `<style>`, разметка-каркас, один `<script>` (`'use strict'`). Порядок в скрипте:

1. Справочники: `CATS` (отделы магазина), `FOODS` (продукты), `MEALS`, `DAYS`, `ACTS`, `GOALS`, `PROGRAM`, `TABS`.
2. Утилиты: `$`, `esc`, `nf`/`n1` (форматирование чисел), `num` (разбор числа с запятой), работа с датами `YYYY-MM-DD` (`dstr`, `parseD`, `shift`, `wdIdx`).
3. Состояние: `blank()`, `normalize()`, `state`, `ui`.
4. Хранение: `readLocal`, `writeLocal`, `save`, `init` (копия данных: `ACT.export`, `ACT.import`, `parseBackup` рядом с `ACT`).
5. Расчёты: `targets` (норма ккал и БЖУ), `food`, `nutr`, `sum`, `sumDay`, `amount`.
6. Отрисовка: `route`, `render`, `view*` по разделам, окно добавления продукта `renderSheet`, `toast`.
7. Действия `ACT` и глобальные обработчики событий.

## Данные

Всё состояние в одном объекте `state` с двумя частями. Раздел на `main` и `log` сохранён из прежней версии с облаком; менять его не нужно.

### state.main (настройки и планы)

```
main: {
  v: 1,
  profile: {set, name, sex:'m'|'f', age, height, weight, act, goal:'gain'|'keep'|'lose', customKcal},
  customFoods: [{id:'c'+base36, name, cat, k, p, f, c, piece:0}],   // свои продукты, на 100 г
  plan: { 0..6: {breakfast|lunch|dinner|snack: [{f:foodId, g:граммы}]} }, // меню недели, 0 = понедельник
  shopChecked: { foodId: true },                                    // отметки «куплено»
  weights: [{d:'YYYY-MM-DD', w:кг}],                                // по возрастанию даты, одна запись в день
  nextWorkout: 'A'|'B',                                             // какая тренировка выбрана
  draft: { A|B: { exerciseId: ['','',''] } }                        // несохранённые повторы
}
```

### state.log (дневник и история)

```
log: {
  v: 1,
  diary: { 'YYYY-MM-DD': {breakfast|lunch|dinner|snack: [{f:foodId, g:граммы}]} },
  workouts: [{d:'YYYY-MM-DD', w:'A'|'B', sets:{exerciseId:[повторы по подходам]}}]  // по порядку записи
}
```

Запись приёма пищи везде одинакова: `{f, g}`, где `f` это id из `FOODS` или `customFoods`, `g` вес в граммах. Калории и БЖУ не хранятся, считаются на лету из справочника (`nutr`). Если продукт удалён, запись показывается как «Продукт удалён» и считается нулём.

`normalize(s)` достраивает недостающие поля поверх `blank()`, так что старые данные открываются после добавления новых полей. Новые поля добавляй в `blank()`, не ломая существующие.

### Хранение

Только `localStorage`, ключ `nabor-v1`, значение: `JSON.stringify(state)`. Любое изменение данных вызывает `save('main'|'log')` (аргумент оставлен ради совместимости, пишется весь `state`). Если запись не удалась, в шапке (`#sync`) появляется «не сохранено». Обращения к `localStorage` всегда в `try/catch`. Облака и `window.claude` в приложении нет и быть не должно.

### Копия данных (профиль)

- «Скачать копию данных» (`ACT.export`) скачивает `nabor-YYYY-MM-DD.json`: `{app:'nabor', v:1, saved:ISO-дата, data:state}`.
- «Загрузить копию» (`ACT.import` + скрытый `#import-file`) читает такой файл (или «голый» `state`), проверяет через `parseBackup`, спрашивает подтверждение и полностью заменяет данные.
- При изменении структуры `state` добавляй поля в `blank()`/`normalize()`, чтобы старые копии продолжали открываться.

## Разделы (маршруты по `location.hash`)

- `#today` Сегодня: дневник калорий за выбранный день, сводка ккал и БЖУ, кнопка «Заполнить день из меню».
- `#menu` Меню: план на неделю по дням, копирование дня на всю неделю.
- `#shop` Покупки: список собирается суммой граммов по всему меню за неделю, группировка по `CATS`, отметки в `shopChecked`.
- `#train` Тренировки: программы А и Б (`PROGRAM`), три подхода на упражнение, подсказка «пора усложнять», история последних 6.
- `#progress` Прогресс: запись веса, график (SVG), подсказка по темпу набора.
- `#profile` Профиль: данные для расчёта нормы (необязательно своя норма `customKcal`) и блок «Копия данных». Вкладки внизу у профиля нет, он открывается по имени в шапке.

Окно добавления продукта (`ui.sheet`): поиск по `FOODS` + `customFoods`, ввод веса, быстрый выбор штук для продуктов с `piece`, форма своего продукта.

## Правила оформления

- Язык интерфейса и текстов: русский. Числа форматировать через `nf` / `n1`.
- Без сборщиков и фреймворков. Скрипты и стили только внутри `index.html`; отдельные файлы только для PWA (manifest, `sw.js`, иконки).
- Никаких сетевых запросов и внешних ресурсов: шрифты системные, всё работает без интернета. Пути к файлам только относительные.
- Репозиторий публичный (GitHub Pages): не класть в него личные данные, копии данных (`nabor-*.json`) и ключи. Автор коммитов с адресом вида `…@users.noreply.github.com`.
- Цвета только через CSS-переменные в `:root` (`--bg --surface --ink --muted --line --red --yellow --blue --green --btn --soft`). Тёмная тема: `prefers-color-scheme` и `data-theme`, цвета переопределяются в обоих местах одинаково. Цвета макронутриентов: белки `--red`, жиры `--yellow`, углеводы `--blue`.
- Шрифты: `--display` для заголовков и крупных цифр, `--body` для текста, оба на системном стеке.
- Вёрстка мобильная, колонка до 640px, отступы 16px, safe-area для iPhone. Нижняя навигация фиксирована.
- Интерфейс строится строками шаблона через `innerHTML`. Любой пользовательский текст оборачивать в `esc()`.
- Действия вешаются делегированием: элемент с `data-act="имя"` вызывает `ACT[имя](dataset)`. Новое действие = новая функция в `ACT` и кнопка с `data-act`.
- После изменения данных: `save(...)`, затем `render()`, при необходимости `toast('Короткое сообщение')`.
- Тосты и подписи короткие, без восклицательных знаков. Опасные действия (удаление) делаются кнопкой «×» или «Удалить запись», без модальных подтверждений, кроме замены всех данных при импорте.
